認証・認可 / Basic認証

認証 → あなたは誰？ 認可 → 何をしていい？

認証とは？

ユーザーが誰かを確認すること
例
ユーザー ログイン
→
サーバー ユーザー確認
→
認証成功

例：ログイン
username: user password: pass

認可とは？

そのユーザーが何をしていいかを判断すること
例
ログイン済
→
管理者？
→
OK / NG
例：
admin → 削除可能 user → 閲覧のみ

Basic認証とは？

ユーザー名とパスワードをそのまま送る認証方式

Basic認証の流れ

リクエスト
→
ユーザー名 パスワード送信
→
サーバー確認
→
OK / NG

コード例

HTTPヘッダ
Authorization: Basic dXNlcjpwYXNz
Base64でエンコードされる
user:pass ↓ dXNlcjpwYXNz

メリット

  • 実装が簡単
  • すぐ使える
例
.htpasswd user:password

デメリット

  • 毎回パスワード送信
  • セキュリティ弱い
GET /api Authorization: Basic xxx
毎回送られる

他の代表的な認証方式（モダン）

① Bearer Token（JWT）

ログイン
→
Token発行
→
API呼び出し
例
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
特徴
  • REST APIと相性が良い
  • ステートレス
  • モダンなWebアプリで多い

② OAuth2 / OpenID Connect

Googleログインなど
アプリ
→
ログインプロバイダ
→
Token取得
例
  • Googleログイン
  • Microsoftログイン
  • GitHubログイン

Cognito の場合

Cognitoはこの流れで使う
フロント
→
Cognitoログイン
→
JWT取得
→
REST API
例
Authorization: Bearer JWT_TOKEN
用途
  • Webアプリ
  • SPA
  • API認証

ユースケース

  • 社内ツール
  • 検証環境
  • 簡易API保護

まとめ

認証 = 誰か確認 認可 = 何ができるか Basic認証 = ユーザー名パスワード送信
